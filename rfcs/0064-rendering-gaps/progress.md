開始日期：2026-10-20。完成：2026-10-21，macOS（Apple M4；Rust 釘在 `rust-toolchain.toml` 的版本）。在 `0064` 上做；第 1 到 4 段各自做完、審核之後先 merge 回 `main`，第 5 段和兩個順帶的修正最後一起 merge。

## 步驟

| 步驟 | 狀態 | 完成日期 |
| --- | --- | --- |
| 1 transform：rotate、skew、`rotateZ`、`transform-origin`、`transform-box`、`-webkit-` 的別名、照 Blink 的插值（第 6 到 11 條） | 完成 | 2026-10-20 |
| 2 版面（第 12 到 20 條）：2a `object-fit`、`object-position` 和 `overflow: clip`；2b `tab-size`（parley fork）；2c line clamp 和 `-webkit-box`；2d `contain` 和 fixed 的包含塊 | 完成 | 2026-10-20 |
| 3 裁切：3a `clip` 和 `clip-path` 的 shape、box；3b SVG 的 `<clipPath>`、`url()`、`clip-rule` | 完成 | 2026-10-20 |

## 做過的檢查

**完成時（2026-10-21，macOS，Apple M4）**：每一段做完時各跑過 `cargo fmt --check`（連同 `sdk/lua/generator`）、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`（第 1 段 3316 個，第 2 段 3356，第 3 段 3375，第 4 段 3396，第 5 段 3428，都通過）和 `sanity.py` 的 `deps`、`boundary`、`unsafe`、`tests`、`docs`；改到的範圍的 `test.py reftest`、`scenarios` 和 WPT 的目錄沒有非預期的結果（下面的 `scrollend` 除外）。第 5 段做完時跑了 `test.py automation`：第一次前 8 份因為視窗一開始沒有顯示出來（螢幕休眠）而失敗，之後的 41 份通過，重跑那 8 份和 `position-sticky` 都通過；`position-sticky` 的截圖裡導覽列和行號欄黏住。第 2 段、第 3 段之後量過 Speedometer，數字記在 RFC 0012 的 `progress.md`。

**每一段做的時候對照 Blink 和 WPT 定下或改掉的**（細節寫在「已決定的事項」的那幾條）：
- **transform**：`skewX`、`skewY`、`skew` 各自一種（Chrome 只和同一種逐項插值，WPT 的 `transform-interpolation-verify-reftests`）；`transform-origin` 的 presentation attribute 每個數字是 px；stroke bounding box 只有路徑擴到斜接角。about:demo 的 spinner 從此會轉，露出動畫原本就有的問題：暫停時存的 hold time 沒有照 Blink 捨入到整數微秒，修好。
- **版面**：做真正的 `overflow: clip`（UA 給 replaced element 的 `overflow: clip` 原本會讓每張圖都成為捲動容器）；`tab-size` 乘的是 block container 的空白（WPT 的 `tab-size-block-ancestor`），fork 的 shaper 把 tab 當成空白 shape（原本畫出缺字的方框）；clamp 的組合的 `display` 照 Blink 換成 `flow-root`，所以做了一般的 `flow-root`；line clamp 照 WPT 修了剛好 N 行、空行、包住第 N 行的 block 的高度、靠右和置中的行；`transform` 在 `none` 和有值之間變時只有裡面有 out-of-flow 盒子才重排；style containment 的 counter 範圍照 Blink 的 `CountersAttachmentContext`；`contain: paint` 的 `<svg>` 兩軸都裁。順帶修了 atomic inline 的 `width: min-content` / `max-content` 當成 `auto` 的問題。
- **裁切**：沒給的中心不寫進 computed value、關鍵字的半徑不插值、`polygon(round)` 的畫法照 Chrome；raster invalidation 比 clip 時連同圓角和路徑一起比（圓角原本就漏了）；`<clipPath>` 在抓的時候讀進形狀，所以算路徑的模組搬到 `layout`；stylesheet 的 `has_unresolved_urls` 原本不看 `clip-path`，別的檔案的 `clip-path: url()` 從不解析（mutation test 抓到），修好。祖先的 `clip`、`clip-path` 裁不到沒被接住的 fixed 盒子（fragment tree 不在同一個子樹），記進限制。
- **文字和效果**：有裝飾線時，陰影全部畫在字和線的下面（Blink 的 `PaintWithTextShadow`）；實線的兩端也對齊像素；`::marker` 收 `text-shadow`；`getComputedStyle` 的 `text-decoration` 照 Chrome 從 style 寫。effect node 建在元素的 clip 和 `clip-path` 之後、記下 output clip（原本模糊和陰影會跑出祖先的 `overflow: hidden`），所以「先 filter 再裁」和規範一樣；根元素的 `filter` 不是包含塊。
- **sticky**：位移連同盒子的位置一起取整（WPT 的 `position-sticky-fractional-offset`）；containing block 扣掉盒子自己的 margin；`getComputedStyle` 的 inset 照 scrollport 解析。compositor 移動的 sticky 的 layer 原本被外面的 clip 裁成空的（kun 自己的 reftest 抓到），改成只被裡面的 clip 裁；sticky 可能移到成為 layer 的容器上時，原本會把容器當成被蓋住，改成 sticky 的範圍是 main thread 的；「外層的 sticky 沒被移動、裡面的也不移動」的條件是多的，拿掉。

**順帶修正的、原本就有的問題**（各自一個 commit）：
- **載入中的 `<img>` 被 garbage collect**（第 2d 段的 WPT 偶爾 timeout）：照 Blink 的 `ImageLoader`，等圖片時用 `NodeHandle` 留住它，frame view 拆掉時一起放掉（第一版留下的 root 讓 3 份 WPT 當掉）。`mutants-img.toml` 4 條。
- **空行不給 baseline**（`contain-paint-010`、`-022`）：只有 out-of-flow 盒子的行照 Blink 的 `IsEmptyLine` 不給 baseline。`mutants-empty-lines.toml` 4 條。

- **absolute 盒子之後的 padding**（`position-sticky-padding-001`、`002`）：scrollable overflow 的結尾 padding 只加在 in-flow 的內容之後（Blink 的 `ScrollableOverflowCalculator`）。`mutants-abspos-overflow.toml` 4 條。
