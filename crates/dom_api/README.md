# dom_api

DOM（`dom`）上和 engine 無關的 API。對應 Blink 裡 DOM interface 的 C++ 實作（`Node::appendChild`），不是替它們產生的 binding：規範的演算法和參數的檢查（名稱合不合法、HTML 文件裡轉小寫），加上每個 engine 綁定用的宣告表（`declare!`、`interfaces`），每個成員一條專用路徑（`typed`）。interface 的物件是節點，或表上寫明的 GC 型別（`Event`，`EventTarget` 是節點或 `new EventTarget()` 的 target）。`dom_js`（V8）和 `dom_wasm`（wasmtime）用它。

不依賴 `v8`，不寫 `unsafe`（`#![forbid(unsafe_code)]`）。

## 一次呼叫

一次呼叫是 DOM 的一個操作：先在操作外轉參數（WebIDL 的轉換可能跑 script，例如物件的 `ToString`），再由 front 開一個操作（getter 是 `Front::read`：共享地借 DOM、`Dom::read`，不經過安全點；setter 和 method 是 `Front::mutate`：`Dom::mutate`），在裡面拿 `this` 和參數的節點、呼叫成員的函式、把結果交給 front 在操作裡的那一側（`OpFront`）；操作結束後，front 才建結果要的 engine 的東西（`Front::finish`：字串、節點的新 wrapper）。engine 配置時可能 GC，V8 驅動的 heap 裡 V8 的 GC 也標 DOM 的 heap，而操作裡的節點不是 root，所以 engine 不在操作裡配置：`OpFront` 借著 front，操作裡碰不到 engine 會配置、會跑 script 的部分（V8 的由借用檢查保證，`dom_js`）。`TypedMember::call` 只拿 front，DOM 由 front 借給每次操作；會呼叫 script 的（`ScriptHost`）也自己開操作，在兩次操作之間呼叫。`#[front]` 的函式拿 `OpFront`。成員的函式拿操作（`ApiCx`）、`this` 和參數（`NodeRef<'gc>`），不建 root。這裡的成員都不呼叫 script；會呼叫的（分派事件、callback）要先把跨過去的物件 root 住、結束操作，再呼叫 script：操作不能巢狀，GC 也要有機會跑。

## 怎麼新增一個 API

1. 在對應的模組（`node.rs`、`element.rs`……）寫函式，照規範的演算法，簽章照上面。參數裡的整數照 `crates/base/README.md` 的規則。
2. 在 `src/interfaces.rs` 的表加一行。需要新的型別時，替它實作 `ArgType`、`RetType`（和 `TypeDesc` 的一種），需要新的參數時在 `Front` 加一個方法。讀 dictionary 的成員的方法（`dict_bool`、`dict_string`…）和 `throw` 在 `DictFront`（`Front` 的上層 trait）：`DictMember::read`、`DictHandle::read` 只要它，front 可以在只有這些方法的東西上讀一個 dictionary（`Front::reading`）。script 那一側才用的方法（呼叫 listener、filter、observer、custom element 的 callback）在 `ScriptFront`（`Front` 的下層 trait）：`WholeCall::run` 和 `FrontHost` 要它，把會跑 script 的成員交給另一個 front 跑的 front 不用實作。`Front`、`OpFront` 新的方法可以給一個會 panic 的預設實作，第一行寫 `const { assert!(Self::STUBS, ..) }`（照其他的）：只綁一部分成員的 front（wasm 的、named property 的、測試的）把 `FrontTypes::STUBS` 設成 true、留著預設；每個成員都經過的 front（V8 那一側的 `InfoFront`）設成 false，成員的呼叫走得到它還沒實作的方法時 build 會失敗，訊息指出是哪個方法、從哪裡呼叫（單態化之後才檢查，所以 `cargo check` 看不到，`cargo build`、`cargo test` 才看得到）。函式在操作裡呼叫得到 `OpFront` 的任何方法，型別看不到它呼叫了哪些，所以 **`OpFront` 的方法要讓每個 front 都有**：不用憑證就能呼叫的方法（`with_array_bytes`、`construct_html`、`new_target_number`、`is_new_target`、`construct_object`…）沒有會 `unreachable!` 的預設實作，front 沒實作就編不過；不綁這類成員的 front 明寫（`unbound_op_methods!`）。新增這類方法時不給預設實作。要 front 「留東西到操作後」的不做成 `OpFront` 的方法：由結果或錯誤帶出操作（要丟的 signal 的 reason 是 `ApiError::Aborted`，帶著 signal 的 root；`ImageData` 的像素是 `ImageDataWithPixels`，`NewImageData` 和 constructor 的 `ConstructPending` 帶出去）。
3. 在 `tests/it/` 用測試的 front end 經過專用路徑呼叫它。
