# style

DOM（`dom`）的 style（對應 Blink 的 `core/css` 的 resolver 和 `StyleEngine`）；和 DOM 無關的部分在 `style_resolver`。和 DOM 無關的 cascade（宣告區塊 cascade 成 computed style、調整、`MatchedPropertiesCache`）用 `style_resolver::cascade`；CSS 的 parse 在 `css`。

不寫 `unsafe`：只用 `dom` 和 elise 的安全 API。

## API

| 型別 | 對應 Blink | 用途 |
| --- | --- | --- |
| `SelectorQuery` | `SelectorQuery`、`SelectorQueryCache` | script 的 selector 查詢（`querySelector`、`querySelectorAll`、`matches`、`closest`）：`parse` 解析一次、名稱在這個 thread 上編號，每個 thread 留著解析過的（256 個，滿了全部清掉），不合法的是 `None`；從 root 往下照樹的順序走（不含 root）。只有一個 id 的、root 是 document 時用 document 的 id 表（`Cx::element_by_id`）。一個 selector、compound 之間只有 descendant 或 child combinator 的，照 Blink 的 `SelectorQuery::MatchCompound` 一個 compound 一個 compound 比：每個 compound 留著一個 id、type、class 和精確比對的屬性（`[a="b"]`、`[a="b" i]`；HTML 照舊規不分大小寫的屬性不留），照 `StyleElement` 的規則直接比（quirks mode 的 id 和 class 不分大小寫、HTML 文件裡 HTML 元素的 type 比小寫的）；往下走時帶著下一個要比的 compound，比到的元素的子孫換下一個，root 和它的祖先從上往下先比掉前面的（Blink 的 `FirstCompoundNotSeenBeforeRoot`）；compound 留不住的（另一個 class、pseudo-class、別的屬性比法）和當成 descendant 的 child，在比到的元素上再完整比對。走到一個元素時，它的子樹的 bloom filter（`Cx::subtree_bloom`）缺這一個和之後的 compound 要的屬性名稱、class 的位元，就整個子樹跳過（Blink 的 `Compound::selector_filter`；quirks mode 不看 class 的，延後寫回的 `style` 屬性不看），debug build 確認跳過的子樹裡沒有比得到的。其他的每個元素完整比對（`:scope` 是元素 root，document 的是 root 元素），比對的 context 一次查詢建一次。debug build 對不記錄狀態依賴的 selector，每個走過的元素都拿完整比對的結果核對（`full_matches_for_testing` 數完整比對了幾個，不算核對的） |
| `StyleEngine` | `StyleEngine`、`StyleResolver` | 一份 document 的 style：`new`（UA stylesheet 的 index 每個 thread 一份，共用）、`set_viewport`（當下看 media query 的結果：有不同、或 device pixel ratio 換了，下一次重新收集、整份重算；只有大小換了，只重算 style 或 pseudo-element 的 style 用到 viewport 單位的元素，有用過才走）、`set_system_colors`（變了時下一次整份重算）、`recalc_style(cx, token, document)`：在 DOM 的一個操作裡，照 DOM 的 style flag 重算變了的部分，用 thread 的 `LocalToken` 寫進元素，清掉經過的 flag |

## 怎麼運作

- **來源**（cascade 的順序）：UA stylesheet（`style_resolver::UA_CSS`）、document 裡照樹的順序的每個 `<style>`（HTML 的和 SVG 的）和 `<link rel=stylesheet>`、元素的 `style` 屬性。這兩種的 sheet 是 DOM 的（`dom::Cx::owner_sheet`：第一次要時建、元素記著，script 的 CSSOM 改的也是那一份，有 `disabled` 的不算）；`<link>` 的由 renderer 載入、交給 DOM（`dom::Cx::set_link_sheet`，`url()` 照 sheet 的 URL；要載哪些照 `dom::Cx::stylesheet_link_href`：`rel` 有 `stylesheet`、CSS 的 `type`、沒有 `disabled`、有 `href`）；`type` 不是 CSS 的不算，有 title 的照 preferred set（第一個不是 alternate 的 `<link>` 的 title，之後就是它），alternate 的 `<link>` 只有在 preferred set 裡才算；`<style>` 和 `<link>` 的 `media` 照 viewport 算（`RuleSet::match_media`，viewport 變了時結果不同就重建）。document 的 sheet 分成幾份 rule index：規則 512 條以上的大 sheet 自己一份，夾在中間的小 sheet 合成一份（每份 index 一個元素要多查一次桶，幾百個 `<style>` 不能是幾百份），照 sheet 的順序 cascade（每份記它前面有幾條規則）；一份 sheet 改了只重建它那一份，其他照樣拿；大 sheet 的 index 照 contents 留著，`media` 不成立時不用、再成立時拿回來。document 的 stylesheet 變了（`StyleFlags::STYLE_SHEETS_CHANGED`：`<link>` 的 sheet 來了、CSSOM 改了也是）時重新收集，sheet 沒換的 contents 是同一個 `Arc`，文字一樣的 `<style>` 共用 DOM 解析的那一份（shadow tree 的也是：同一個 rule index）；收集到的和上次不同時，只重算變了的規則可能配到的元素（下面的「sheet 的 invalidation」）。`style` 屬性的宣告是 DOM 的那份（`Cx::inline_style`：從屬性 parse 一次留著，或 CSSOM 改過的），`ElementStyle::inline` 存 cascade 用的那個 `Arc`。SVG 的 `<use>` 的 copy（`dom` 的 UA shadow tree）的元素比對 copy 外的那個 `<use>` 所在的樹的規則（document 的，或它的 shadow tree 的），當成它自己比對：它的樹到 copy 的根為止，`defs rect` 不配 `<defs>` 裡的 rect 的 copy（Blink 的 `ScopedStyleResolverFor` 拿 corresponding element 的樹）；照 flat tree 從 `<use>` 繼承。
- **rule index**（`src/rule_index.rs`，Blink 的 `RuleSet`）：從 `css::RuleSet`（規則和 media query 的結果）照每個 selector 最右邊的 compound 分桶：id 照值的表裡的字串的位址（index 拿著它；id 不進名稱表，免得清單的 id 一直留著），class 照名稱表裡小寫的編號，tag 照寫的和小寫的編號，其他的一桶。quirks mode 的 document 每個 id 的 selector 都是候選。建的時候替 selector 用到的名稱（tag、class、命名空間、屬性的 local name，`:is()` 這類裡面的也是）在這個 thread 上編號，記在 `css::IdentAtom`（帶 thread 的序號，別的 thread 讀到不算數），也記下 selector 在祖先位置用到的名稱和用到的 combinator（`Features`）。
- **比對**（`src/selector.rs`）：`selectors::Element` 的新 DOM 版本，名稱比編號、id 比文字；`:hover`、`:active`、`:focus`、`:focus-within`、`:focus-visible` 讀元素的 bit（document 的鏈，`dom`），`:defined` 讀元素的 custom element 狀態（uncustomized 或 custom），`:lang()` 讀元素或最近的祖先的 `lang`（shadow tree 的往上到 host），都沒有時是 document 的 content language（`dom::Cx::content_language`），`:target` 讀 document 的 target element，它們的改變經過 DOM 記下的狀態 bit 和 invalidation set 重算；`:window-inactive` 讀 window 的 page 有沒有 focus，page focus 改變時有規則用它就整份重算；`:host`、`:host()`、`::slotted()` 照 `selectors` 的（`containing_shadow_host`、`assigned_slot`，比對時給 shadow tree 的 host，`:host` 的規則對 host 是 featureless 的）；表單的 `:checked`、`:indeterminate`、`:disabled`、`:enabled`、`:required`、`:optional`、`:read-write`、`:read-only`、`:placeholder-shown`（input 和 textarea 的）、`:default` 比對時問 DOM（`dom` 的 `form_state.rs`，Blink 的 `IsChecked` 這些），它們的改變經過 DOM 記下的狀態 bit（`AttributeChanges` 的 `CHECKED`、`INDETERMINATE`、`DISABLED`、`VALUE`、`DEFAULT`）和它們讀的屬性（`pseudo_class_attributes`：例如 `type`、`required`、`readonly`）的改變重算；驗證的那些、`:target` 還沒有，不符合；`option` 和 `optgroup` 的還沒有。表單控制項的 UA shadow tree 的 part（有 shadow pseudo id 的元素，`dom` 的 `ua_shadow`）：它的 host 那棵樹的 part 的規則（rule index 的 `parts`：`input::-internal-inner-editor`、`::placeholder` 這類；UA 的，和 host 所在的 tree scope 的 author 的，document 的或那棵 shadow tree 的）把它當作 host 的 pseudo-element 比對（`StyleElement::shadow_pseudo`：`::` 之後是 host），在 css-scoping 的順序裡是 host 那棵樹的；host 重算時它的 UA shadow tree 一起重算。native look（`effective_appearance`，`style` 的 `FormControl`，Blink 的 `LayoutTheme::AdjustAppearanceWithElementType`）照元素的名稱和 input 的 type、select 是不是 menu list、part 的 shadow pseudo id 給 cascade。比對前先查祖先的 bloom filter（`src/bloom.rs`：走下去時 push 元素的 tag、namespace、id、class 的 `name_hash`，回來時 pop；namespace 也要放：UA stylesheet 的預設 namespace 是 HTML 的，它的每個 compound 都比 namespace，`selectors` 把它算進祖先的 hash）。
- **invalidation set**（`src/invalidation.rs`，Blink 的 `RuleFeatureSet`）：建 rule index 時，每個 class、id、屬性、狀態記下 descendant set（祖先的 compound 用到它時，子孫裡要重算的：subject 的一個特徵，id、class、屬性、名稱裡最少見的；沒有時是整個子樹）和 sibling set（sibling combinator 左邊用到它時，後面幾個兄弟、哪些、它們本身或它們的子孫）；`:empty` 的 sibling set；set 說不出的（shadow tree 的元素的 selector、`:nth-child(… of S)`、`:is()` 裡的兄弟）退回整個子樹或後面每一個兄弟，從後面數的（`:nth-last-child(… of S)`）連前面的兄弟也標起來，由第二趟走；狀態只看比對時查過的（`dom::Cx::state_dependencies`：`input:focus` 的 `:focus` 不是 `<div>` 的），元素自己和它的 set 都是；子節點來去時照父節點（或 shadow root）的 selector flags、規則看得到幾個兄弟（`Features::sibling_reach`）和兩邊的 `FOLLOWS_CHANGE`、`PRECEDES_CHANGE` 挑要重算的子元素（舊的 engine 的 `children_to_restyle`，Blink 的 `CheckForSiblingStyleChanges`）；`lang`、`dir` 改了時整個子樹。在 style 那一趟裡套用：屬性或狀態改了的元素走到時查 set，descendant 的特徵往下帶給每個子孫（有那個特徵的重算），sibling set 帶給後面的兄弟（照 reach），不另外走一遍、不記在元素上（DOM 只記改了什麼，不認得 rule：屬性改了也不再標下一個兄弟）。debug build 的交叉檢查：set 之前的粗的規則會重算、set 跳過的元素重新 cascade 一次比對（`set_verify_for_testing` 可以關掉，給測「沒有交叉檢查時往不往下走」的測試）；`restyled_for_testing` 是上一次重算過的元素。
- **adopted 的 sheet**（`adoptedStyleSheets`，Blink 的 `TreeScope::adopted_style_sheets_`）：document 和 shadow root 的都排在它自己的 sheet 之後；disabled 的留在清單裡（重新啟用時才找得到 adopt 它的 scope），規則不算。sheet 換了 contents 或 `disabled` 時，DOM 把它放進清單（sheet 不記哪些 scope adopt 它），style 在走之前拿走、照上一次收集的找 adopt 它的 scope：document 的重新收集，shadow root 的標成 sheet 變了（`mark_shadow_sheets_changed`，走精細的那條）；比對新舊照 contents 的 `Arc`，只重算來去的規則找到的。同一個 sheet adopt 到很多 shadow root 時共用一個 index。
- **shadow tree 自己的 sheet**（`src/shadow_sheets.rs`，Blink 的 `ShadowTreeStyleSheetCollection` 和 tree scope 的 `ScopedStyleResolver`）：shadow root 裡照樹的順序的 `<style>` 和 `<link>`（title 在 shadow tree 裡不算，alternate 的 `<link>` 不套用，照 Blink），`media` 照 viewport。`dom` 記下 sheet 可能變了的 shadow root（`<style>`、`<link>` 來去、文字或屬性變了，巢狀的 shadow tree 的也是；host 標上 `STYLE_SHEETS_CHANGED`），style 在走之前拿走、重新收集（`<link>` 的 sheet 來了或 viewport 變了時每一個都收）；走的時候只讀。變了的：和 document 的一樣比對新舊的 sheet，來去的規則可能配到的重算（`rule_set_invalidation`）：那棵 tree 裡有它們的特徵的元素（document 的不算）、`:host` 的規則變了時 host、`::slotted()` 的變了時 slot 分到的（經過幾層 slot 都算）、找不到特徵的或順序變了的整棵 tree 加 host 和 slot 分到的（Blink 的）；沒收過的 shadow root 照沒有 sheet 比。DOM 標了 host 時走訪到那裡、往下每個元素查自己的特徵（`Down::look`）；DOM 沒標的（`<link>` 的 sheet 來了）host 連同子樹重算。debug build 照樣檢查跳過的元素不配任何變了的規則（比對時給那棵的 host）。host 和 slot 分到的元素自己的改變：`:host(.a)`、`::slotted(.a)` 只重算它自己（它的屬性變了本來就重算），`:host(.a) p` 由 host 的 shadow tree 的 descendant set 找 `p`。一千個同樣的 component 共用的：`<style>` 的文字相同時解析好的 contents，每份 contents 一個 rule index（Blink 的 `RuleSet` 跟著 `StyleSheetContents`），shadow root 的元素照它的 sheet 的順序比對每一個。shadow root 不在了、或不在 document 裡時放掉它的，沒有 shadow root 用的 contents 和 index 也放掉（scope 多到門檻時一起看；一棵的 sheet 換掉時，舊的 contents 沒有別棵在用就當場放掉）。元素比對的（`Walk::sources`，css-scoping 的 cascade 順序）：UA 的；它的 tree scope 的（document 的，或它的 shadow tree 的，比對時 host 是那棵的）；它經過的每個 slot 的那棵 shadow tree 的 `::slotted()` 規則，從最近的開始；host 自己的 shadow tree 的 `:host` 規則。不同 tree 的宣告比較時，普通的外面的勝、`!important` 的裡面的勝（`CascadePriority::tree`）。invalidation set 照元素的 tree scope 的 index（和 host 的 shadow tree 的：`:host(.a) .b`）；交給 DOM 的名稱也包括 shadow tree 的 sheet 用到的。
- **sheet 的 invalidation**（`src/rule_set_invalidation.rs`，Blink 的 `InvalidateForRuleSetChanges`）：新舊的 sheet 照 contents 和 media 的 `Arc` 對，兩邊都有的照順序留著（順序變了時整份重算），來去的 sheet 的規則（media 符合的）減掉兩邊都有的（同一個規則的 `Arc`、前面留著的 sheet 一樣多、順序一樣，Blink 的 `RuleSetDiff`）就是變了的規則。每條 selector 的 subject 的特徵（id、class、屬性、名稱，`:is()` 的每個 subject）找到要重算的元素；沒有時往左找第一個有特徵的 compound：祖先的找到要重算的子樹，兄弟的變成 sibling set；都沒有、有 `:has()`、`@keyframes` 時整份重算；media query 的結果變了也是。特徵存成雜湊表（一份 sheet 的規則很多，不是每個元素掃一遍清單）。重算那一趟走遍整份（每個元素查自己的特徵；shadow tree 裡的元素不查，document 的規則不配它們）；debug build 在走完後檢查被跳過的元素不配任何變了的規則。
- **分到 slot 的節點的兄弟**：走訪照 flat tree，兄弟的 set 本來只傳給同一個 slot 裡後面的節點；分到 slot 的節點（parent 是 host）的 sibling set 改成當場沿 DOM 的兄弟套用，配到的、在 flat tree 裡的標成要重算（`dom::Cx::set_needs_style_recalc`，連子樹）。走訪已經走過的（在前面的 slot 裡），走完之後再走一趟有標記的路徑。插入和移除不用：host 的子節點一變，slot 本來就整個重算。
- **DOM 只記 style 讀的改變**（`dom::StyleNames`，Blink 的 `StyleEngine::AttributeChangedForElement` 改的當下查 invalidation set 的那一部分）：每個 rule index 建的時候收集它的 selector 在任何位置用到的 class、id、屬性、狀態，pseudo-class 讀的屬性（`invalidation::pseudo_class_attributes`：`:link` 的 `href`、`:open`、`:lang`、表單的那些讀的屬性），有 `:has()` 時全部；sheet 變了（或 `attr()` 讀到新的屬性）時，UA 和 author 的聯集加上 presentational hint 的屬性、`style`、`lang`、`dir`、`<body>` 的 `link`、`alink`、`attr()` 讀過的，交給 document（`set_style_names`）。DOM 不記、不標其他的改變：沒有 rule 讀的屬性改了，元素不再重算。名稱過期時（script 加了用到新名稱的 sheet，在下一次 recalc 之前改了那個名稱）照樣對：sheet 的 invalidation 照元素現在的特徵找。debug build 的檢查：DOM 把沒記的留著，重算之後確認每一個都不會讓 set 找到別的元素（那之間 sheet 沒變時）、元素重新 cascade 和它的 style 一樣；有沒記的時重算不提早結束。
- **走訪的兩半**：每個元素先算「影響到誰」（`Walk::invalidate`：屬性、子節點、規則的變化，加上祖先和前面的兄弟交下來的 `Down`，得出 `Invalidation`：自己、子樹、每個子元素、帶給子孫的特徵、帶給後面兄弟的），再「重算它」（cascade、往下走）；兄弟之間帶的在 `Siblings`。
- **重算**（`src/lib.rs`）：從 document 往下照 flat tree 走（`dom::Cx::flat_tree_children`：host 的是 shadow root 的子節點，slot 的是它分配到的節點，從它繼承；開始前 `recalc_slot_assignments` 先算完過期的分配），只走 flag 說下面有變的地方（和 invalidation set 說要看的地方）。document 的 sheet 不配 shadow tree 裡的元素；分配到 slot 的節點在 light tree 裡，照樣配。新的、搬過的元素連同子樹重算；屬性或 `:hover`、`:active` 的狀態改了的重算自己，和 invalidation set 找到的子孫、兄弟；算出來的繼承值或 `display` 變了時子元素重算；`+`、`~` 和照 selector 旗標的 structural（`:nth-child()` 這類）讓位置變了的兄弟重算，有 `~` 時後面的兄弟都重算；子節點變了時，有 `:empty` 的元素重算自己；有 `:has()` 或 root 的 font size 變了時整份重算。wheel listener 來去時（`dom` 標）元素重算自己：有會阻擋的就給 `inside_blocking_wheel_event_handler`（`has_own_blocking_wheel_listener`，root 的也算 document 和 window 的；pseudo-element 照它的元素），繼承給下面。算出來一樣時留著舊的 `Arc`，變了時告訴 layout（`set_style_changed`），pseudo 的也是。
- **cascade**：元素和它的 `::before`、`::after`、`::marker` 同一趟比對，各自 cascade（`style_resolver::cascade::cascade_blocks`），`::before`、`::after` 的 `attr()` 換成元素的值。
- **presentational hints**（`src/hints.rs`）：HTML 的屬性對到 CSS 的（list、table、`<body>`、`<font>`、`<hr>`、`<img>` 和 `<iframe>` 的寬高），parse 是 `style_resolver` 的（`style_resolver::html_hints`），這裡只讀屬性（`style_resolver::HintSource`）、找 cell 的 table、算屬性的 digest（matched properties cache 的 key）；每次 style 一個元素時算（有的元素少，cell 的還看它的 table），當成 author 的、specificity 0、排在所有 author 的規則之前；table 的 `cellpadding`、`border`、`bordercolor` 變了時整個子樹重算。`<body>` 的 `link`、`alink` 是 document 的 link 的顏色，變了時整份重算。
- **SVG 的 presentation 屬性**（`hints.rs`）：哪個元素有哪個屬性和 parse 是 `style_resolver` 的（`style_resolver::svg_hint`、`svg_hint_declarations`），這裡照元素的屬性的順序讀、經過照屬性的名稱的編號和值的快取（`style_resolver::PresentationAttributeCache`，每次 recalc 從 engine 移進 walk、再移回；path 的 `d` 不進快取），和 HTML 的 hint 一樣當成 specificity 0 的 author 宣告；它們的名稱都交給 DOM 記下改變（`svg_hint_attribute_names`）。
- **`::selection`**：在 walk 裡和元素一起比對（比對成元素自己的 `::selection`，originating element 是它自己），元素的 highlight 照它自己的規則和 parent 的（css-pseudo-4 的 highlight inheritance，共用的 `style_resolver::cascade_highlight`，Blink 的 `ResolveHighlightStyles`）；沒有規則配到的照 parent 的往下傳。invalidation 把它當元素自己的規則（不是 UA shadow tree 的 part）。
- **動畫和 transition**（和 DOM 無關的步驟用 `style_resolver::animation_style`）：每個元素和它的 pseudo-element cascade 之後是它的 style change event：照 `animation-name` 開始、保留、取消 CSS animation（keyframe 從元素自己的 shadow tree、它的 tree scope 往外到 document 找，每個 keyframe 在元素上以 animation origin 再 cascade 一次，`Recascade`），再開始、取代、取消 transition，給出加上它們在 document timeline 的時間（`Cx::animation_time`）的值的 style；動畫存在元素上（`Cx::style_change_animations`），事件排進 document。walk 往下帶著祖先有沒有 `display: none`（有的話取消）、有沒有移除過又回來的根（`Cx::removed_since_styled`：它的 style 是之前的，不從它開始 transition）、parent 的 style 有沒有變（有動畫的子元素再算：keyframe 可能 `inherit` 它的值；有過動畫之後，style 變了的元素 walk 都往下看它的子元素）；有過動畫之後，`display: none` 來去時整個子樹再算。只有時間前進的元素（`Cx::take_animations_moved_on`，推進時標好路徑）把值套到上次的 base style、不重新 cascade，動畫的是繼承的 property、`font-size` 或 script 的 keyframe 還沒算時才重新 cascade；pseudo-element 不在了時取消它的動畫。
- **還沒有**：背景屬性的 `url()` 照 base URL 解析。
