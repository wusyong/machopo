# dom

照 elise（`../third_party/elise`）的規則重做的 DOM（對應 Blink 的 `core/dom`）。現在有：節點樹（DOM 的七種節點：document、doctype、document fragment、element、text、comment、processing instruction）、名稱、屬性、文字、template 的內容，和 parser 也會用的 DOM 演算法（插入、移除、設屬性、clone）；style 和 layout 讀的狀態（flag word、dirty bit、子樹的 bloom filter）；event target 的 listener 和分派；shadow tree、slot 和 flat tree；custom element；window、timer 和 task、frame tree、導覽和 history；collection、`MutationObserver`、`Range`、`Selection`、traversal；表單和控制項的 UA shadow tree、editing；圖片、canvas、SVG 的 `<use>`；CSSOM 的 sheet、動畫的物件；各種 observer 和 Web API（`fetch`、`Blob`、`FileReader`、`performance`、idle callback、`AbortSignal`……）的 DOM 那一側。給 engine 的 API、參數的檢查（名稱合不合法、HTML 文件裡轉小寫）在 `dom_api`；`html` 的 `parser` 把 html5ever 的結果建在它上面。

不寫 `unsafe`（`#![forbid(unsafe_code)]`）：只用 elise 的安全 API，論證在 elise 的 [`soundness.md`](../../../third_party/elise/docs/soundness.md)。

## API

| 型別 | 對應 Blink | 用途 |
| --- | --- | --- |
| `Dom` | 一個 thread 的 `ThreadState` 和它的 heap | 一個 DOM：heap（名稱和屬性值的表是 thread 的，見「字串和名稱」；`Dom` 不是 `Send`，節點存的名稱編號只在建它的 thread 上有意義）。`mutate` 跑一個操作（開始前是安全點，heap 可能先 GC），`read` 跑一個不配置的操作（不經過安全點，`elise::Heap::read`；借共享的 `&Dom`，這種操作可以重疊，不會和 `mutate`、GC 重疊），`collect` 在安全點做 full GC，`stats`，`should_collect` 是 heap 該不該 GC（wasm 的 host 函式在 Store 借出時經過 Store 做），`heap_mut` 把 heap 借給 GC 物件和節點放在一起的 engine（wasm 的：經過 bits 配置和寫、它的 frame、store 在兩次呼叫之間拿著的 root 的來源、交出 stack 的 root 的 GC；借出，不換掉它：節點是 DOM 的），`interned_values` 是這個 thread 的屬性值的表現在的大小。JS 文件的 heap 由 V8 驅動（`HeapOptions::driven`）：`start_marking`、`advance_marking`、`finish_marking` 是 V8 的 major GC 的那一側，在操作之間呼叫，`used_bytes` 是告訴 V8 的大小；`walk` 在安全點上跑一個走遍 heap 的每個物件的操作（`elise::Heap::walk`，heap snapshot 用），`Cx::is_detached` 是物件是不是不在任何文件的樹裡的節點（不是節點的是 `None`；Blink 在 snapshot 裡給節點的 detachedness） |

`Cx` 的操作：

- 建節點：`create_document`（HTML 文件或 XML 文件，決定 `nodeName` 的大小寫；`set_xml_document_interface` 讓它是 `XMLDocument`；content type、encoding、`currentScript` 在它的 `DocumentData`，host 設，沒設的 content type 和 encoding 是預設的）、`create_element`（名稱已經檢查過；`create_element_named` 給已經在表裡的名稱；HTML 的 `<template>` 同時建它的內容）、`create_text`、`create_comment`、`create_processing_instruction`（target 已經檢查過）、`create_doctype`、`create_document_fragment`；`document_of` 是節點的 node document（document 自己是自己的）；`clone_node` 是 DOM 的「clone a node」（可以給別的 document；`deep` 時連同子孫，template 的內容也複製）。
- Template：`template_content` 是 template 的內容（一個 fragment，在 document 的 template 文件裡）；`template_document` 是 document 給 template 內容用的 inert 文件（HTML 的「appropriate template contents owner document」，第一次用到才建，和原本的文件同樣是 HTML 或 XML）。
- Shadow tree（`shadow.rs`，Blink 的 `ShadowRoot`、`TreeScope`）：`attach_shadow`（檢查是呼叫的一方的：`shadow_host_check` 是 DOM 的 attach a shadow root 對元素本身的檢查，HTML 的那幾個元素或合法的 custom element 名稱、定義沒有停用 shadow，`attachShadow` 和 parser 共用；host 的 `ElementData` 指向它，不會拿掉；host connected 時它也是）、declarative 的旗標（`is_declarative_shadow_root`、`set_shadow_root_declarative`：parser 給的，`attachShadow` 接手時拿掉）、`set_template_content`（parser 的 declarative shadow root 是它的 template 的內容）、`shadow_root`、`shadow_host`、`is_shadow_root`、`shadow_root_init`（`ShadowRootInit`：mode、delegates focus、slot assignment、clonable、serializable）、`containing_shadow_root`（讀 `owner`，一次）、`parent_or_shadow_host`、`is_in_shadow_tree_of`（往外一個 tree scope 讀一次，不走樹的深度）、`retarget`（DOM 的；不在 shadow tree 裡的一次讀取就回答）、`is_closed_shadow_hidden`（user agent 的 tree 也是 closed）、`root_node`（`getRootNode`：shadow tree 裡和 connected 的是一次讀取，其他的往上走）。子樹搬進、搬出 shadow tree 時走一遍改 `owner`（`set_shadow_scope`，Blink 的 `TreeScopeAdopter`），換 document 時走進 host 的 shadow tree（它們的節點的 `owner` 不變）；插入、移除的那一遍（connected、id、stylesheet）走進 shadow tree，但 shadow tree 裡的 id 和 stylesheet 不是 document 的（`getElementById` 在 shadow root 上走子樹，和 fragment 一樣）；clone 時 clonable 的 shadow root 跟著 host（deep 與否）。還沒有 flat tree，style 和 layout 還不看 shadow tree。
- Slot（`slot.rs`，Blink 的 `SlotAssignment`、`HTMLSlotElement`）：slot 是 shadow tree 裡的 HTML `<slot>`（`is_slot`）。shadow root 的資料記著它的 slot（樹的順序）和兩個過期的 bit（slot 的清單、分配）；slot 的 `ElementData` 掛著 `SlotData`（分配到的節點、`assign` 給的節點）；slottable（host 的子節點裡的 element 和 text）的 rare data 記著它分配到的 slot 和 `assign` 給的 slot。分配要用時才算（`recalc_slot_assignment`，在會配置的操作裡：`assigned_nodes`），`assigned_slot` 不配置（過期時照名稱找）。named：每個子節點給同名的 slot 裡樹的順序第一個（`slot` 屬性，text 是空的名稱）；manual：照 `assign` 給的順序，還是 host 的子節點的才算（`assign` 把節點從它之前的 slot 拿走）。`flattened_assigned_nodes` 是 DOM 的 find flattened slottables（沒有分配到的節點時用 slottable 的子節點，裡面的 slot 換成它的）。DOM 的 signal a slot change：要觸發 `slotchange` 的 slot 記在 `MutationState` 的 signal slots（同一個只記一次，和 observer 的 microtask 一起排；`take_signal_slots`）。哪些 slot 要 signal：host 的子節點進出、`slot` 屬性改變時，只找它的名稱找到的那個 slot（和舊名稱找到的，manual 的插入不 signal，照 DOM），分配標成過期，不重算整個；slot 進出 shadow tree、`name` 改變（比較少）時馬上重算，比較每個 slot 前後分配到的節點，有變的 signal，離開的 slot 有節點的也 signal。「之前」是用之前的 slot 清單（只有這裡會重做它，所以一定是變更前的）、改名前的名稱和現在的 host 的子節點重新算的，不是存著的清單（可能過期）。slot 的 fallback 內容變了、它又沒有分配到的節點時也 signal。插入、移除和屬性的 hook 只在 parent 是 host、在 shadow tree 裡或是 shadow root 時（`scope` 的 bit，一次讀取）、屬性是 `slot` 或 `name` 時才進冷的路。
- Form owner（`form.rs`，Blink 的 `ListedElement` 和 `HTMLFormElement` 的元素清單）：listed element（HTML 命名空間的 `button`、`fieldset`、`input`、`object`、`output`、`select`、`textarea`，`is_listed`；名稱表的 `FORM_KINDS` 一次讀，也有 labelable 和 `<form>` 的 bit，`is_labelable`）的 form owner 在它的 `ElementData`（`FormAssociation`），在 DOM 的操作裡當場重設（HTML 的 reset the form owner：`form` 屬性在 connected 時照 id 找它的樹裡第一個元素、是 form 才算，否則最近的祖先 form，不經過 shadow root 到 host）：插入時子樹裡的每個 listed element（parser inserted flag 設著的不動）、移除時子樹裡 owner 留在外面的、移除的 form 的 owner 在外面的元素（只在 parser 或 `form` 屬性給過它外面的元素時找）、`form` 屬性改了、connected 的子樹進出和 id 改了時有 `form` 屬性的元素（DOM 記著它們的 id，`FormState`）。第一個 `<form>` 建立（`create_element_named`）、第一次有 `form` 屬性、parser 第一次關聯之前，插入和移除只讀一個旗標。parser 的關聯（`set_parser_form_owner`）設 parser inserted flag（節點的 `PARSER_INSERTED`，和 script 的同一個 bit），插入時保留 owner，重設時清掉。form 的元素照樹的順序在它的 `FormAssociation`，問到時找（它的子樹，外面可能有時是整棵樹），留到某個 owner 改變（`form_walks` 是測試用的計數）；`form_named_item` 是 `form[name]`（`id` 或 `name` 是它的：一個是元素、記進 past names map，幾個是 `RadioNodeList`，沒有時看 past names map；元素的 owner 改了時從 map 拿掉），`form_controls_named_item` 是 `elements.namedItem`。`<img>` 沒有 owner。`<label>` 的 labeled control（`label_control`：有 `for` 時是它的樹裡第一個有那個 id 的元素、是 labelable 才算，沒有時是第一個 labelable 的子孫）和 `form`（`label_form`）、`<legend>` 的 `form`（`legend_form`：父節點是 `<fieldset>` 時是它的 owner）每次問都找，DOM 的操作不為它們留任何東西。
- disabled（`form.rs`，Blink 的 `ListedElement::IsActuallyDisabled`）：`is_disabled_form_control` 是 `button`、`fieldset`、`input`、`select`、`textarea`（名稱表的 `DISABLABLE` bit）有 `disabled` attribute，或在有 `disabled` 的 fieldset 裡、不在它的第一個 `<legend>` 子節點裡。祖先怎麼說在第一次問時往上走一次，記在 `FormAssociation`（Blink 的 `ancestor_disabled_state_`），子樹插入和移除、fieldset 的 `disabled` 改了、fieldset 的 `<legend>` 子節點進出時改回未知（`disabled_walks` 是測試用的計數）；第一個 `<fieldset>` 建立之前不記、插入和移除不看。
- `<img>` 的圖片（`image.rs`，Blink 的 `ImageLoader` 和 `MemoryCache`）：元素的 `ElementData` 在第一次更新時有一個 `ImageLoader`：current request 和 pending request（狀態、網址、圖、等它的 `decode()`）、更新的次數（舊的 microtask、抓取、task 什麼都不做）、它延遲 load event 的 document（`DocumentData::load_delay`，`load_event_delayed`）。「update the image data」：`src`、`srcset`、`sizes`、`crossorigin`、`referrerpolicy` 改了（名稱表的 `CONTROL_ATTRIBUTE` bit，`kind` 是 0 的元素看是不是 `<img>`）或 adopt 時，快取有的圖當場是 current request、排 `load`；沒有來源時當場清掉（Blink 的 loader 對空的網址當場清）；其他的排 microtask（`Microtasks::images`，`run_image_update`），在那裡照 node document 的 URL 解析、建 request（current 有圖時是 pending）、從快取拿或排抓（`Dom::take_image_fetches`）；host 抓回來交給 `image_fetched`（失敗的離開快取），等它的 request 做完（pending 的升成 current）、排 `load` 或 `error`（window 的 element task 帶 `ImageTaskAction`，`take_image_event`）。快取（list of available images）是 DOM 的、整個 renderer 一份（照網址；載入中的也算，另一個 `<img>` 選了它就等同一個抓取），背景圖也用（`background_image`、`cached_image`）；每筆記著用它的文件（抓它的、從快取拿它的、背景圖的），文件 shutdown 時（`release_document_images`：導覽離開的 `unload_document`、iframe 移除和子 frame 導覽的 discard）放掉，沒有文件用的拿掉（Blink 的 memory cache 是 weak 的，`ResourceFetcher` 留著文件用過的；request 拿著的圖照樣在）。快取裡載入中的圖也當場接上（Blink 的 `ShouldLoadImmediately`）；microtask 選到 current 等著或有的同一張圖時保留 current（`decode()` 不被 reject，有的再發一次 `load`）。用 `srcset` 或在 `<picture>` 裡的不走同步的那條路，來源由 engine 在 microtask 選好交給 `run_image_update`（網址和 density：natural 的大小是圖的除以它，四捨五入）；`<picture>` 的 relevant mutations：`<img>` 進出、它前面的 `<source>` 進出或改了 `srcset`、`sizes`、`media`、`type`（建 `<picture>` 時設 `PICTURES_SEEN`，插入和移除的 hook 讀一個 bit）。這些 `<img>` 在第一次更新時記進 document 的清單（`responsive_images`，weak），環境改變時重新選；同一張圖只換 density（`set_image_density`）。沒有 window 的 document 的 `<img>` 不載入。layout 讀 `image_state`。圖片（`Image`）是 host 解碼的檔案和它的大小，或 host 做成的 SVG 圖片（它的編號和 natural size：`naturalWidth` 照 `SvgNaturalSize::dom_size`，density 只換算圖給的那一邊、不換算預設的 300×150，給 layout 的照 density 換算；canvas 不畫它）。環境改變時的重新選（`reselect_image`，HTML 的 react to environment changes）失敗時不發 `error`（`ImageEvent::fire`）。
- `loading=lazy`（`image.rs`，Blink 的 `LazyLoadImageObserver`、`ImageLoader` 的 `lazy_image_load_state_`）：更新開始時（同步的那一段；`loading` 在 microtask 之前改了時重新看，parser 一個一個設屬性）記下這次更新是不是 lazy（`loading` 是 lazy、有 window），這種更新的 request 不延遲 load。microtask 裡要抓的 lazy 的 request（list of available images 沒有的，Chrome 的 `ShouldLoadImmediately`）等著（`deferred`），document 的 lazy load observer 觀察它：每份 document 一個內部的 intersection observer（`DocumentData`，第一張 lazy 的圖才建），上下 1250px、左右 625px，同時是 root margin 和 scroll margin（Chrome 只給 scroll margin，它的 viewport 也算；`paint::intersections` 只把 scroll margin 給 target 和 root 之間的捲動容器）。`resume_lazy_image`（它的 entry 相交時、`loading` 變成 eager 時）不再觀察、排 microtask，microtask 抓它等的那個網址（`sizes="auto"` 的重新選）。`sizes="auto"`：`allows_auto_sizes`（lazy，`sizes` 是 `auto` 或 `auto,` 開頭），每份 document 一個內部的 resize observer（`observe_auto_sizes`，在 window 的 resize observer 裡排第一，Blink 的 `kBeforeOthers`）。背景圖要的網址另外記（`background_images_loading`）：load 等它們和延遲的計數。
- Intersection observer（`intersection.rs`，Blink 的 `IntersectionObserver`、`IntersectionObservation`、`IntersectionObserverEntry`）：observer（callback 和 wrapper 是 engine 的、選項建了之後不變、explicit root 是 weak 的，root 不在了時 `intersection_observer_root` 是 `Gone`、不是 implicit root）在 window 的清單上（weak，照建立的順序）；observation 在 target 的 `ElementData` 的清單上，target 撐著它、它撐著 observer（沒有 script 拿著的 observer 在它觀察的東西還在時還在），observer 的清單是 weak 的。observation 記著上一次的 threshold index（第一次之前沒有，所以第一次一定有 entry）、是不是相交、是不是 visible、上一次算的時間（observer 的 `delay` 從那裡算）。建 observer、`observe`、`unobserve` 換 `intersection_version`（renderer 看它決定要不要 frame、要不要重算）。entry 建了之後不變，排在 observer 的佇列，第一個有 entry 的 observer 讓 window 的 task 排進去（`queue_intersection_entry` 回答），其他的照拿到第一個 entry 的順序等著（`take_pending_intersection_observers`）；`take_intersection_entries` 是 `takeRecords()` 和 task 的。
- Resize observer（`resize.rs`，Blink 的 `ResizeObserver`、`ResizeObservation`、`ResizeObserverEntry`）：observer（callback 和 wrapper 是 engine 的）在 window 的 weak 清單上；observation 在 target 的 `ElementData` 上，target 撐著它、它撐著 observer，observer 的清單是 weak 的。observation 記著觀察的 box（content、border、device-pixel content）和上次報的大小（第一次之前沒有，所以第一次一定送）。同一個 box 再 `observe` 什麼都不做（報過的大小留著，同 Blink 的 `observeInternal`），換了 box 是新的、排到最後。`observe` 換 `resize_version`（renderer 看它要 frame）。entry 建了之後不變，它的三個大小（`ResizeObserverSize`）每次是同一個物件。
- `<canvas>`（`canvas.rs`，Blink 的 `HTMLCanvasElement`、`CanvasRenderingContext2D`）：元素的 `ElementData` 撐著它的 2D context（`getContext("2d")` 第一次建、之後同一個），context 撐著元素，帶著建立時的設定和資料（`canvas` crate 的 `CanvasData`：狀態的堆疊、錄下還沒畫的 op、bitmap；拿出來再放回，`with_canvas_data`）。`canvas_size` 照 `width`、`height` 屬性（HTML 的非負整數，預設 300×150），layout 也用；它們改了（值一樣也算）時 context 重設到預設的狀態、新的大小，又是 origin-clean，canvas 要重建 box（Blink 的 `HTMLCanvasElement::ParseAttribute`）。`record_canvas_draw` 記下有 op 要畫的 canvas（一個一次、照第一次的順序）和加一的 `canvas_draws_version`（renderer 照它要 frame），`take_canvas_draws` 取走，`keep_canvas_draws` 放回沒畫的。狀態的 style 是漸層或圖案時，`CanvasGradient` 或 `CanvasPattern` 在 context 的 slot 裡（每一層兩個，fill 和 stroke，Blink 的 `CanvasRenderingContext2DState` 拿著它的 `CanvasStyle`），和狀態的堆疊一起動：`save_canvas_state`、`restore_canvas_state`（放掉那一層的）、`reset_canvas_context`；`set_canvas_style`、`canvas_style_object`（`CanvasStyleObject`）。`CanvasGradient` 的幾何和 stop、`CanvasPattern` 的圖（做的時候的樣子）、重複的方式和 transform 是 plain data（`with_canvas_gradient`、`with_canvas_pattern`，拿出來再放回）；`ImageData` 記著大小、色彩空間和撐著像素的 `JsEdge`（engine 的 `Uint8ClampedArray`，front 設，`image_data_array_edge`，Blink 的 `ImageData` 拿著它的 `DOMUint8ClampedArray`），三個都不屬於哪個 realm。`<img>` 當 canvas 的圖片來源時是 `image_for_canvas`（`ImageForCanvas`：還沒有圖可畫，包括 update 的 microtask 排著、或有 pending request 的時候，照 Chrome 的 `ImageComplete()`；broken；或圖、它自己的大小、密度和是不是 origin-clean：可用的圖片的清單記著沒有 CORS、從別的 origin 來（opaque 的回應）的 URL，host 在 `image_fetched` 時說）。`toBlob` 的呼叫（`request_canvas_blob`）是一個 `CanvasBlobCallback`（編號、canvas、callback 的 `JsEdge`、檔案的型別、檔案來了之後的 `Blob`），在 DOM 的清單裡（root 住）等它的檔案；要編的（`CanvasEncode`：編號、`canvas::export::ExportBitmap`、編碼）由 host 取走（`Dom::take_canvas_encodes`）、在別的 thread 上照順序編，`canvas_encoded` 把檔案做成 `Blob`、排 element task（`ElementTaskKind::CanvasBlob`），task 裡 `take_canvas_blob` 拿出來；canvas 的 document 那時沒有 window 的就丟掉。HTML 的演算法在 `dom_api`（和 `canvas::context`、`canvas::path`、`canvas::pixels`、`canvas::image`、`canvas::export`），畫 op 和編碼在 renderer。
- 文字（`canvas.rs`）：`TextMetrics`（`measureText` 的數字，做的時候的樣子；不屬於哪個 realm）；document 的 canvas 的 font 的快取（`parse_canvas_font`，Blink 的 `CanvasFontCache`：字串到 `css` 解析的結果，不是 font 的也記，最多 `MAX_CACHED_FONTS` 個、先進先出；在 `DocumentData` 裡，拿出來再放回）。元素的 directionality（`directionality.rs`，HTML 的：`dir` 不分大小寫、`auto` 和沒有 `dir` 的 `bdi` 看第一個 strong 的字元（不看 `bdi`、`script`、`style`、`textarea` 和有自己的 `dir` 的元素），否則 parent 的，最上面是 ltr；問的時候才算，canvas 的 `direction = inherit` 用它；machopo 的 style 沒有 `direction`）。
- SVG（`svg.rs`）：`SvgAnimatedString`（元素和屬性的名稱，元素的 data 留著，每次同一個；值是屬性的）。SVG 元素的屬性改了（連上的）就標成要重建（`set_needs_reattach`：屬性是它的幾何，layout 抓的 `<svg>` 的內容過期了）；SVG 的 `<style>` 和 HTML 的一樣擁有 sheet；HTML 和 SVG 的元素都有 event handler 的屬性。
- SVG 的 `<use>`（`svg_use.rs`，Blink 的 `SVGUseElement`）：參考的元素 clone 進 `<use>` 的 UA shadow tree（closed，script 拿不到；`use_copy` 是 copy 的根、`use_tree_host` 是 copy 所在的 `<use>`、`outermost_use` 是不在 copy 裡的那一個：style 照它的樹的規則比對 copy）。copy 留下 SVG 的元素（不畫的也留著，Blink 的一樣：`defs + rect` 這種 selector 看得到）和 text，不留 `<script>` 和 SVG 以外的；copy 裡的 `<use>` 跟著 clone 進它自己的；循環（參考自己，或往上（經過 copy 的根到它的 `<use>`）到第一個不是 SVG 的元素為止有一樣的 id 的，Blink 的 `HasCycleUseReferencing`）不 clone，一個 copy 外的 `<use>` 連同裡面的超過 `MAX_COPIES`（10000）個元素時整個不畫（Chrome 全 clone，machopo 不讓頁面無限地長）。第一個 `<use>` 建立之後，copy 外 connected 的 `<use>` 記在清單裡（id、它和 copy 裡的 `<use>` 查過的 id 和找到的元素、clone 過的元素），host 在 style 之前呼叫 `update_use_trees`（Blink 的 `BuildPendingResource`）：剛 connected 的、`href`（和 `xlink:href`）改了的、clone 過的元素或它們裡面有變動的（屬性、子節點、text 的資料：往上找祖先，只在有 `<use>` 時）、有 id 變動且查過的 id 找到別的元素的重建，離開的拿掉 copy、忘掉；沒有變動時不走清單。
- `Path2D`（`canvas.rs` 的 `Path2d`，Blink 的 `Path2D`）：它的路徑（`gfx::Path`，拿出來再放回，`with_path_2d`），`CanvasPath` 的方法在上面建，context 拿它當時的樣子畫、clip、hit test；不屬於哪個 realm。
- `Blob`（`blob.rs`，Blink 的 `Blob`、`BlobDataHandle`）：bytes 和型別，不會變（`External<BlobData>`），不屬於哪個 realm。bytes 是一份 `Arc<[u8]>` 和其中的一段：`slice` 和原本的共用同一份（真的有好幾個擁有者），之後 fetch 的 body、worker 的訊息也要把它帶到別的 thread。`File` 是同一個 GC 型別：`BlobData` 多一個可有可無的 `FileInfo`（名稱、修改時間），`slice` 出來的是 `Blob`；`shared_bytes` 是送給 browser 的 blob URL 的 bytes。

## 配置

- **掛在節點上、和它活得一樣久的資料配在節點的那一代**（elise 的 `Mutation::alloc_beside(node, ..)`、`HeapVector::new_beside`）：element data、rare data、文字和屬性、屬性的清單、classes、`childNodes` 的 list、input 的型別、表單關聯、`Attr`、doctype、template 和 document 的資料。engine 驅動的 heap 裡節點一開始就在 old（有 JS 邊的型別都是），它的資料配在 nursery 的話，每次掛上記一筆 old 到 young，scavenge 還要複製兩次（Blink 的 DOM 在 Oilpan 上，節點和資料都在 old）。有 wrapper 的型別（`classList` 這類）本來就在 old，用 `alloc_in`。新增掛在節點上的資料時照這條；`gc::a_nodes_data_is_allocated_beside_it` 檢查 engine 驅動的 heap 裡常見的操作不用 nursery。
- 只活一下子的（事件的資料和路徑、暫時的清單）用 `alloc_in`；renderer 的 heap 沒有 nursery，它們一樣配在 old，由 full GC 收。

## 字串和名稱

- **名稱**（`src/names.rs`）：element 和屬性的 local name、前綴、命名空間都在同一張表，同一個字串同一個編號，節點只存編號（不用配置、沒有 finalizer、比名稱就是比編號）。**每個 thread 一張**（Blink 的 thread 的 `AtomicStringTable`）：parser、DOM 和 style 直接 intern，不經過 `Dom`；同一個 thread 上的每個 DOM 共用編號。
  - **固定的名稱**：DOM 自己的（命名空間、`nodeName`、編號 0 到 16 的常數）和 HTML、SVG、MathML 的 local name（`fixed_names.txt`，html5ever 的靜態 atom 的清單，來自 web_atoms，`MIT OR Apache-2.0`），再加上這些 local name 轉大寫的形式（HTML 文件裡 HTML 元素的 `tagName`；Blink 的 `QualifiedName` 也記著自己的大寫名稱），再加上 Blink 的 event type（`event_type_names.txt`，`event_type_names.json5` 的 362 個，包括 machopo 還沒有的功能的；已經在的不重複，沒有大寫的形式），由 `build.rs` 在編譯時產生：每個固定名稱的大寫是第幾號也是一個陣列，`tagName` 不碰表；編號找字串讀陣列，字串找編號用 perfect hash（CHD，和 `phf` 同一種做法，但 hash 是 8 bytes 一步的 FxHash 加 murmur3 的收尾，`src/name_hash.rs`，`build.rs` 和查詢共用：`phf` 的 SipHash 讓 JS 的 `createElement` 每次多 250 條指令），都不碰表、不借用；每個 local name 有常數（`names::local::DIV`，Blink 的 `html_names::kDivTag`：大寫、`-` 和 `:` 換成 `_`、SVG 的大寫字母前加 `_`，`clipPath` 是 `CLIP_PATH`，和它撞名的屬性 `clip-path` 是 `CLIP_PATH_ATTR`；`*` 是 `STAR`），event handler 的屬性名稱（`event_handlers.txt`：GlobalEventHandlers、WindowEventHandlers 和 window-reflecting 的清單，Blink 的那一份）也在，照編號查得到它處理的 type 和屬於哪一組（`names::handler_attribute`，編譯時產生的表），清單是 `names::GLOBAL_EVENT_HANDLERS`、`WINDOW_EVENT_HANDLERS`、`WINDOW_REFLECTING`；每個 event type 也有（`names::event::CLICK`，Blink 的 `event_type_names::kClick`：大寫、camel case 的字之間加 `_`，`DOMContentLoaded` 是 `DOM_CONTENT_LOADED`；和 local name 同名的，如 `input`，是同一個編號）。`fixed` 是 `const fn`，給編譯時算好的表（元素的介面）用。
  - **其他的名稱**在 thread 的表裡（`RefCell`：沒有擁有者可以借，借用不跨出函式、借著時不呼叫外面），編號接在固定的之後，查表用 FxHash。`get` 給固定的名稱 `&'static str`、其他的給它的 `DomString`（多一個參照），借用不留到呼叫之後；`string` 給 `DomString`（固定的名稱的在 thread 上第一次要時才做）。空字串（沒有命名空間、沒有前綴）直接是 `NONE`，不查表：長度 0 的 `memcmp` 在 glibc 的 AVX-512 版本仍然讀 page 0，在 Zen 4、5 上是幾百 cycles 的 assist。
- **字串**（`src/string.rs`）：DOM 的字串在規範上是 16-bit 的 code unit（WebIDL 的 `DOMString`）；這裡存 UTF-8，machopo 的 parser、style、排版、wasm 都讀它。從 JS 來的字串可以有落單的 surrogate，UTF-8 存不下：等 JS 寫得進來時，那種字串存成 WTF-8，`to_str` 只對它們給把 surrogate 換成 U+FFFD 的副本。ASCII 的字串的 bytes 就是它的 Latin-1，UTF-16 的位置就是 byte 的位置。
- **計數不是 atomic、字串是 thread 自己的**（`Rc<str>`，Blink 的 `StringImpl` 也是）：`DomString` 不是 `Send`，編譯器擋住跨 thread 的 clone 和 drop。所以最後放掉它的地方也在同一個 thread：heap 上帶字串的物件（屬性、文字的資料、doctype 的 id、document 的 URL、event 和 listener 的 type、`ErrorEvent` 的訊息）用 `elise::LocalExternal`，在 heap 的 thread 上 finalize（`External` 的值要是 `Send`，在 sweep 的 worker 上 finalize）；engine 把它複製成自己的字串，不借它的 buffer（V8 在它的 GC 的 worker 上放掉 external string 的 buffer；而且量起來借比複製慢：快取沒中的 `getAttribute` 複製快 22%，100 bytes 的值也一樣）。和 atomic 的 `Arc`、finalizer 在 worker 上、借 buffer 給 V8 比：`set-attribute`、`className`、`create-text-node`、`text-content` 的量測頁快 8% 到 15%（finalizer 在主 thread 上時 `free` 走配置的 thread 的快路，每個 18 ns，在 worker 上 49 ns）。
- **qualified name 是一個編號**（`QualifiedName`，Blink 的 `QualifiedName` 是一個指標）：節點和屬性各存 4 bytes，不是三個編號的 12 bytes，`Node` 因此放得下 `u32` 的旗標和 id。幾乎每個名稱（沒有前綴、命名空間的編號 0 到 3）都直接是 bit，`createElement`、`getAttribute` 不因此查表；elise 的一般資料只能是數字，所以節點上存 `raw` 的 `u32`。
- **照名稱找屬性**（`getAttribute` 這類）先把名稱查成編號（表裡沒有的名稱不會是任何屬性的，直接沒有），再對每個屬性比整數，不拿名稱的字串。
- **屬性值 intern**（`Values`，Blink 的 `AtomicString` 的表，每個 thread 一張，intern 時借一次）：相等的值是同一個字串（engine 照位址快取它做的字串，同樣的值在每個元素上都命中）；文字節點的資料不 intern。值在 GC 的 finalizer 裡放掉，finalizer 可能在 worker 上跑、碰不到表，所以表長到上一次留下的兩倍（至少 64）時，才把只剩表拿著的值丟掉：每個 intern 平均是固定的成本。

- `names.rs`：每個固定的編號讀回的名稱找得回同一個編號（perfect hash 和 `fixed` 都是）；常數是它們的名稱（DOM 自己的編號不變、SVG 的大小寫和撞名的屬性）；其他的名稱的編號接在固定的之後、每次一樣，固定的名稱不佔表的編號；名稱的 `DomString` 每次給同一個；同一個 thread 的 DOM 共用名稱、別的 thread 看不到；轉大寫的 `nodeName` 只做一次，固定的名稱轉大寫也是固定的編號、不佔表的編號；沒有前綴、四個命名空間的 qualified name（固定的和其他的 local name）讀回一樣、不查表，有前綴、別的命名空間的在表裡編號一次、讀回一樣，`is` 不管前綴；有前綴的 element 和屬性的名稱讀回完整的、照 qualified name 和命名空間都找得到。
- `style.rs`：class 照寫的和小寫的編號、去掉重複的，換掉、拿掉 `class` 屬性之後再讀時跟著變，脫離 document 的元素也是；插進 connected 的樹時節點要重算、parent 的子節點變了、祖先都標上、box 要重建，標到已經標過的祖先就停，前面的 sibling 標上；脫離 document 建的樹不標、插進去時整棵 connected，拿出來之後不再 connected、改它不標也不記；移除時 parent 和前後的 element sibling（跳過 text）標上；屬性變了記下屬性的名稱、加減的 class、前後的 id，標上自己、下一個 sibling 和 parent，拿走之後沒有、清 flags 時丟掉，還要整個重算的 element 不記；text 的資料變了標 parent 和 text 的 box，comment 不標；`<style>`、`<link>` 來了、走了、`<style>` 的文字和 `<link>` 的屬性變了時 document 的 stylesheet 變了，別的元素不會；樹的版本每次改都加一（脫離 document 的也是）；id 第一次要時才給、之後同一個、節點死了找不到；element 的 style 用 token 寫、讀成參照（不 clone），selector flags 只加不減、不是 element 的每個 bit 都是 1。
- `custom_elements.rs`：reaction 排在最裡面的範圍的 element queue，第一次排時才推、沒排的範圍不推，巢狀的範圍各自的，外面的留著；每個元素的 reaction 是它的 upgrade、一次；副本做出來時排、不是定義的名稱的不排；沒有範圍時進 backup queue，microtask 排一次，處理中進來的同一輪處理，處理完再進來的再排一次。合法的名稱的 HTML 元素是 undefined（`div`、保留的名稱、SVG 的不是），副本也是，每種狀態讀回一樣、不動 shadow 的 bit；connected 時記下的候選照 shadow-including 的樹的順序拿（外面建好再一起插進來的、shadow tree 的在 host 的子節點之前），沒插進來的、插進來又拿出去的不算，別的名稱各自的、已經定義的名稱不記，拿過一次就空了；候選是 weak 的（拿出去、丟掉的經過 full GC 不在），一直插入又丟掉時用量不跟著長；construction stack 的推、頂端、marker、取出；建構子的編號找到它的定義（同一個編號兩個）；元素的定義、照名稱找定義、`upgradable_under`。registry 只建一次、window 留著它（經過 full GC）；定義照順序、照名稱找得到，名稱、local name、observed attributes、`disabledFeatures`、「element definition is running」；`whenDefined` 的編號每個名稱一個、各自不同，取走之後沒有、再加是新的編號；合法和不合法的 custom element 名稱（新的規則的空白、`/`、`>`、NUL，保留的名稱，BMP 以外的字）。
- `intersection.rs`：`observe` 每個 target 一次、不是 element 的不算，`unobserve`、`disconnect` 拿掉，建 observer、`observe`、`unobserve`、`disconnect` 換 version；observation 的狀態；target 撐著 observer（沒有 target 的 observer 收掉、離開 window 的清單）；explicit root 是 weak 的；entry 的佇列和等 task 的順序、拿走之後清空、entry 撐著 target。
- `resize.rs`：`observe` 只收 element、同一個 box 不變（報過的留著）、換 box 排到最後，`unobserve`、`disconnect`，observe 換 version；target 撐著 observer（沒有 target 的收掉、離開 window 的清單）；entry 撐著 target、它的 rect 和大小，大小每次同一個物件。
- `gc.rs`：有 root 的樹經過 scavenge 和 full GC，連結、屬性、文字和 node document 都還在（開著 heap verifier）；root 放掉之後整棵收掉；借出的 heap 是 DOM 自己的（engine 的 frame 裡操作的安全點不 GC）；engine 驅動的 heap 裡，建節點、設屬性、classes、`childNodes`、表單、parser 的 fast path、`Attr`、doctype、template 都不用 nursery（節點的資料跟著節點配在 old）。
- `probes.rs`：有人要時依序記插入（連同前一個兄弟節點）、移除、屬性、文字、inline style、shadow root，拿走一次；沒人要時不記，不要了時丟掉記著的。
- `initiators.rs`：要 stack 時 script 改的 `<img>`、連上的 `<link>`、script 元素、iframe 和 `fetch()` 記下來，拿到操作之後的 stack（先記的留著，只拿一次），沒有 stack 的不留，清掉的、不要時的不記；只要 frame 的時只記 iframe；parser 設著行號時不記；`<img>`、background（有沒有 stylesheet）、script 元素和 module 的抓取帶著誰發起的。
